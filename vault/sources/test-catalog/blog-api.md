- New: defined, sources sufficient, no test. Gap: partly covered, or blocked; the blocker type is
  named (missing access, source conflict, missing source). Covered: an existing test asserts the
  expected result, with run evidence.

### How one row is derived (TC-API-010)

1. Requirement (S15 AC1): "Login happy path returns token AND fully-populated user object — guards
   the empty-user serialization bug."
2. Contract (OAS, 2026-10-28): `POST /api/auth/login` requires `email` and `password`; 200 returns
   `token` (string) and `user` with `id` (integer), `email`, `display_name`, `role`, `bio` (null or
   string), `created_at`; the token is also set as an httpOnly cookie.
3. Database (DB, 2026-10-28): `users.role` is NOT NULL with CHECK `admin` or `author`;
   `display_name` and `email` are NOT NULL; `bio` is nullable; `password_hash` exists in the table but
   not in the contract.
4. Expected: the contract's six fields with their types, values that prove identity (AUTHOR's email,
   role `author`), and no `password_hash` (an inference, kept as Q10). An empty `{}` user fails,
   which is the bug the case guards.
